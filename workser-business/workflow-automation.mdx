## Node categories

Workflows are built from nodes across these categories: `core`, `trigger`, `action`, `transform`, `logic`, `productivity`, `communication`, `database`, `file`, `utility`, `ai`, and `computer_use` — spanning HTTP requests, sandboxed code execution (Node.js/Python), conditionals, database actions, third-party app actions, AI agent/employee/chat steps, browser automation, and desktop computer-use steps.

## Execution model

Workflows run as a directed graph — each node consumes the outputs of the nodes upstream of it. Every run's inputs, outputs, and per-node results are logged so you can debug after the fact.

## Connected apps

Third-party actions go through an integration layer, so you authorize a connection once (OAuth or API key) and any workflow in your organization can use it, scoped to what you approved. See [Connections & Integrations](/workser-business/connections-integrations).

## For enterprise teams

- Connected-app credentials are encrypted at rest and scoped per organization.
- Workflow execution history — including any customer data that passed through it — currently has no fixed retention limit by default. If your organization needs a specific retention window, raise it with your Workser contact; it isn't enforced automatically today.

## For self-serve builders

Start from a template, or build node-by-node on the canvas. Plain triggers (webhook, schedule, manual) don't consume credits — AI-evaluated triggers do.
