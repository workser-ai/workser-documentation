title: "Workser Desktop FAQ"
description: "Troubleshooting and common questions for computer use and Workser Code."
---

<AccordionGroup>
  <Accordion title="The agent can't take screenshots or control my mouse/keyboard">
    Check that Workser Desktop has Screen Recording and Accessibility permissions in your OS privacy settings (macOS) or the equivalent on Windows — see [Install & Setup](/workser-desktop/install-setup). These are requested on first use of a capability that needs them; if you denied the prompt, you'll need to grant it manually in system settings.
  </Accordion>
  <Accordion title="Windows shows a security warning when I install">
    This happens because the current build isn't code-signed yet. Click "More info" → "Run anyway" to proceed, or wait for the signed version — you can register for that waitlist from the download page.
  </Accordion>
  <Accordion title="Workser Code doesn't detect my coding-agent CLI">
    Confirm the CLI (Claude Code, Codex, or OpenCode) is installed and already authenticated in your terminal — Workser Code connects to an existing, working CLI session rather than installing or authenticating one for you. Cursor, Gemini CLI, Kimi Code, Grok, and Muse Code are wired in but currently switched off — see [Workser Code](/code/connect-your-agent#supported-agents) for why.
  </Accordion>
  <Accordion title="Is Workser Code sending my code to Workser?">
    No — under Workser Code's bring-your-own-key model, code generation happens through your own connected coding agent and its own provider account. Workser's cloud only receives what's needed to deploy and host the result (git operations, environment variables, domain/billing calls). See [Workser Code](/code/overview).
  </Accordion>
  <Accordion title="Can I use computer-use and Workser Code at the same time?">
    Yes — they're independent subsystems. Computer-use controls your screen/input at your direction; Workser Code deploys what your own coding agent builds. Using one doesn't require the other.
  </Accordion>
  <Accordion title="Can I use my own coding agent (Claude Code, Codex, etc.) inside Computer Use?">
    No — Computer Use always runs on Workser's own hosted model. Bringing your own agent subscription is Workser Code's job, for deploying code, not for screen/mouse/keyboard control. See [Computer Use's model section](/workser-desktop/computer-use#model).
  </Accordion>
  <Accordion title="Do I need to pay Workser separately for AI to use Workser Code?">
    No, not for code generation — Workser Code is bring-your-own-key, so your existing coding-agent subscription (Claude Pro/Max, ChatGPT Plus/Pro, etc.) covers that. You do need an active paid Workser plan (Spark or above) for the hosting/deploy side once your 7-day free trial ends. See [Workser Code's pricing section](/code/pricing).
  </Accordion>
  <Accordion title="What happens when my 7-day free trial ends?">
    If you haven't subscribed to a paid plan, Workser Code and other paid-tier features pause — your project and its data are **not** deleted, they're just inaccessible for further building/deploying until you subscribe. See [Payments & Billing](/consumer/payments-billing).
  </Accordion>
  <Accordion title="How do I revoke computer-use access?">
    Revoke the OS-level Screen Recording/Accessibility permissions at any time in your system privacy settings, or uninstall Workser Desktop — both immediately stop any further computer-use actions.
  </Accordion>
</AccordionGroup>
