## Three ways an AI agent reaches an app

| Way | Use it when |
| --- | --- |
| A connected app | The app is in the catalog. You authorize it once and the AI agent uses its actions directly: fastest and most reliable. |
| The cloud browser | The app is a website without a connection, or the task needs its screens. Save the [login](/ai-workforce/logins-and-computers#logins) once. |
| The cloud computer | The task needs a desktop app or several apps at once. |

## Connect an app

1. Open your project's connected apps, or the **Apps** tab on an AI agent.
2. Choose the app and sign in to it, or paste its API key if it uses one.
3. Choose which AI agents may use it.

If a task needs an app that isn't connected yet, the AI agent asks you to connect it.

Give an AI agent access only to the apps a task needs.

## Connections stay in their project

A connection belongs to the project where you made it. AI agents in another project can't use it, so each client or brand you keep in its own project stays apart.

## How credentials are protected

Connection tokens and API keys are encrypted at rest and never shown again once saved. Removing a connection stops every AI agent from using it from then on.

## Automations from app events

An [Automation](/ai-workforce/automations) can start when something happens in a connected app, like a new order or a new form entry.
