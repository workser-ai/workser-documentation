Start with a clear, testable project. For example: a booking page where customers choose a service and time, and your team can see and manage the bookings.

<Steps>
  <Step title="Download and sign in">
    Download Workser Code for **Mac with Apple silicon** from [workser.ai/code](https://workser.ai/code). The desktop app is free. Windows is on the waitlist.

    Sign in with your Workser account. New organizations start with **7 days of Spark free, with no card required**. See [Install & setup](/workser-desktop/install-setup).
  </Step>
  <Step title="Choose your coding agent">
    Connect Claude Code, Codex, Cursor Agent, GitHub Copilot or OpenCode, or select the built-in Workser Code agent.

    Connected agents use their provider accounts and limits. The built-in agent uses Workser credits for paid model usage. The Spark trial covers cloud features, not an unlimited AI allowance. [Connect your agent](/code/connect-your-agent).
  </Step>
  <Step title="Create a project and describe the work">
    Create your project and the app you want to build. Tell the agent who will use it, what data it needs and what should happen when someone completes the main action.

    > Build a booking page for my studio. Customers choose a class and reserve a place. Staff can see attendance and cancel a booking. A class must never accept more bookings than its capacity.

    Review the proposed plan and role assignments. Add the documents or business rules the team needs. Provision the project's database, authentication and files as the app needs them.
  </Step>
  <Step title="Follow the work and try the preview">
    Inspect tasks, handovers and check results. Try the main customer flow in Preview, including sign-in, saved data, validation and error states. Ask for changes in the same project.

    A passing build is useful evidence, but does not prove every business rule works.
  </Step>
  <Step title="Approve production, then keep improving">
    Review the release destination and approve publication when the app is ready. Production deployment is a separate decision from building and previewing.

    Test the published address. Later fixes continue with the project's existing tasks, documents, decisions and code.
  </Step>
</Steps>

## Connect the tools your project needs

You can authorize app connections such as Slack, Gmail or Sheets. Your agents can use them while developing or maintaining software, and your finished app can call their actions through server-side code. Read [App connections](/code/app-connections) before using a real account in a test.

## A few useful habits

- Define the result and acceptance checks before a large task starts.
- Keep credentials in the environment settings, never in a chat message.
- Inspect the preview and check evidence before approving a release.
- Use task handovers and project documents to preserve decisions for the next change.
- Check [cloud allowances and model credits](/code/pricing) before expanding a workload.
