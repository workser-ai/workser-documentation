## Before you download

<AccordionGroup>
  <Accordion title="What is Workser Code?">
    A desktop workspace where coding agents work as one team to plan, build, test, publish and maintain software. Workser adds shared project context and managed cloud services.
  </Accordion>
  <Accordion title="Do I need to know how to code?">
    You can describe the work in plain language and review it in Preview. You still need to explain business rules, test important flows and decide what is ready. Complex or sensitive software may need a developer's review.
  </Accordion>
  <Accordion title="Which agents can I use?">
    Claude Code, Codex, Cursor Agent, GitHub Copilot and OpenCode, plus the built-in Workser Code agent. Each external CLI uses its own provider account and limits. [Connect your agent](/code/connect-your-agent).
  </Accordion>
  <Accordion title="What if I do not have an AI subscription?">
    Use the built-in Workser Code agent with credits for paid models, or configure OpenCode with a model available through your provider. A free OpenCode model depends on provider availability. Spark's cloud trial is not an unlimited model allowance.
  </Accordion>
  <Accordion title="Can I use different agents for different roles?">
    Yes. Assign a supported agent and model to each role, with instructions, skills, tools and references. The thirteen roles are grouped into Plan & design, Build, and Test, launch & improve. [The AI team](/code/roles).
  </Accordion>
  <Accordion title="Which computers are supported?">
    The current public download is for Macs with Apple silicon. Windows is on the waitlist. See [Install & setup](/workser-desktop/install-setup).
  </Accordion>
</AccordionGroup>

## Plans and usage

<AccordionGroup>
  <Accordion title="What am I paying for?">
    The desktop app is free to download. Workser cloud plans start at $10/month. Connected coding agents use their provider accounts; the built-in agent uses Workser credits. Cloud overage and other hosted services can add usage charges. [Full pricing guide](/code/pricing).
  </Accordion>
  <Accordion title="Do I need a card for the trial?">
    No. A new organization gets 7 days of Spark free. Spark includes no monthly model credits; top-ups are available. Paid cloud features can pause when the trial expires without a subscription.
  </Accordion>
  <Accordion title="How are built-in agent credits calculated?">
    Actual reported model cost plus 15%, converted at 100 credits per dollar and rounded at settlement. A $1 model cost uses 115 credits. It is not a fixed per-step fee or a weekly allowance.
  </Accordion>
  <Accordion title="Can Spark use a custom domain?">
    Yes. Custom domains are included in the current Spark offer. You purchase the domain separately and configure DNS. [Cloud allowances](/code/pricing#compare-plans).
  </Accordion>
  <Accordion title="What happens above the cloud allowance?">
    Published rates are $1.25/GB for database storage, $0.15/GB for files and $0.50/GB for egress. Automatic overage depends on the meters enabled for your organization. Project, app and team member limits require an upgrade. [Cloud overage](/code/pricing#cloud-overage).
  </Accordion>
  <Accordion title="Does it keep working when I close my Mac?">
    Published software runs on its hosting. Agent Cloud runs hosted product agents. Local coding agents need your Mac and required tools running to continue development.
  </Accordion>
</AccordionGroup>

## Building and maintaining software

<AccordionGroup>
  <Accordion title="What does Workser add to a coding agent?">
    Roles, project channels, goals, tasks, documents, decisions, handovers, checks and managed deployment. The same project context helps you continue after the first release.
  </Accordion>
  <Accordion title="Can agents use my apps, and can my software use them too?">
    Yes. Agents can use authorized connections while developing or maintaining a project. Your software can call the same available actions from its backend using the SDK. Your app must enforce its own end-user permissions. [App connections](/code/app-connections).
  </Accordion>
  <Accordion title="Does all my code stay on my machine?">
    No blanket local-only promise applies. A connected agent sends model requests to its provider; the built-in agent uses Workser-managed model access. Shared project records, sync and deployment also use cloud services. [Security & approvals](/code/security-and-approvals).
  </Accordion>
  <Accordion title="What happens before an app goes live?">
    Try the preview, inspect check evidence and approve the production release. Successful checks do not guarantee every business rule is correct. [Preview & publish](/code/preview-and-publish).
  </Accordion>
  <Accordion title="Can it build a mobile app?">
    Yes. Preview on a device and use the available distribution routes. Store submission is currently disabled in the desktop release. [Mobile apps](/code/mobile-apps).
  </Accordion>
  <Accordion title="Is Agent Cloud a hosted Codex or Claude subscription?">
    No. Agent Cloud is a beta hosted runtime for agents inside your product. Each agent has a published configuration, selected models and bounded access to tools, connections and workflows. Your local coding-agent subscription does not pay for its hosted runs. [Agent Cloud](/code/agent-cloud).
  </Accordion>
  <Accordion title="How does this relate to Workser Business and Computer Use?">
    Workser Business documents the existing web platform, workflows and AI Employees. Computer Use is a separate desktop capability for screen and input tasks. They share your Workser account, but their execution and usage rules differ.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Workser Code doesn't see my agent" icon="magnifying-glass">
    Workser Code checks two things: is the CLI on your `PATH`, and is it actually **authenticated** — by inspecting credential files, the OS keychain and environment variables.

    So an agent that's installed but not signed in won't appear as connectable. Run its own login command (`claude /login`, `codex login`, …) in a terminal, then re-check in Workser Code.

    Also confirm you're using the CLI, not just the desktop app of the same name — Cursor's CLI binary, for instance, is `cursor-agent`, not `cursor`.
  </Accordion>
  <Accordion title="`not_connected` (exit 4)" icon="plug-circle-xmark">
    The CLI can't find the Workser Code daemon. Open Workser Desktop. If you're running standalone or in CI, run `workser login` instead, then `workser doctor` to see what endpoint resolved.
  </Accordion>
  <Accordion title="`awaiting_approval` (exit 5)" icon="hand">
    Working as intended — something with a real consequence is waiting for you in Workser Code. Approve it there, then your agent retries. It's not an error to work around.
  </Accordion>
  <Accordion title="`owner_only` (exit 6)" icon="user-lock">
    Your agent tried something reserved for you: creating or switching a project, or deleting an environment variable. Do it yourself in Workser Code and carry on. See [what your agent can never do](/code/security-and-approvals#owner-only-cli-actions).
  </Accordion>
  <Accordion title="`no_project`" icon="folder-open">
    No project is linked to this folder. Link it in Workser Code, or pass `--project <id>` explicitly.
  </Accordion>
  <Accordion title="`needs_local_app`" icon="laptop">
    You're on a machine that has only the CLI and a token, so the file-based commands (`checkpoint`, `restore`, `sync`) can't run. Every read-only command still works.
  </Accordion>
  <Accordion title="`workser doctor` points at the wrong environment" icon="wrench">
    The session file records the endpoint it logged in against, so changing `$WORKSER_ENV` afterwards doesn't move an existing session. Run `workser login` again, or pass `--endpoint` explicitly.
  </Accordion>
  <Accordion title="`sync` says `diverged`" icon="code-branch">
    Both your folder and Workser changed, and sync stops rather than picking a winner. Resolve it in Workser Code rather than forcing it through.
  </Accordion>
  <Accordion title="`regionSupportsNeonBackend: false`" icon="globe">
    Final, not retryable. A project's region is fixed when it's created, and the Neon backend (`workser neon storage` / `functions`) isn't available in yours. Use the default bucket — `workser storage` — which every project has.
  </Accordion>
  <Accordion title="The workflow runs but nothing appears in the app" icon="arrows-turn-right">
    The classic one. A workflow feature is two-way: triggering it is the outbound half, and the workflow's final node has to POST back to a webhook route in your app for the result to land anywhere. See [the SDK's workflows section](/code/sdk#workflows).
  </Accordion>
  <Accordion title="A shell command or SQL statement was refused" icon="ban">
    Read the refusal and the operation it names. Agent permissions, protected paths and destructive-operation checks can stop a command. Do not bypass the refusal. Use the project's migration and approval workflow for schema changes, and inspect [Security & approvals](/code/security-and-approvals).
  </Accordion>
</AccordionGroup>
